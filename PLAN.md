# Plan

What Baseplate is building next, and why. The specs in `implementations/` are the generic 50% of a game's *code*. This plan covers the generic 50% of everything else: how the game looks, sounds and ships.

## 1. Component library: VFX + sounds (building now)

**The problem.** Ship a v0 Roblox game and you hit the same wall every time:

- **No music, no sounds.** The options are low-quality community audio with unclear licenses, assets that get deleted and break silently, or making it yourself.
- **VFX is a time sink.** Custom particles have a thousand ways to go wrong (lifetimes, curves, light emission, cleanup). That's not where a v0 should spend its time.
- **The open-source VFX that does exist isn't agent-native.** One pack lives in a Discord, one file per message. No search, no install, no way for an agent to use it.

**The answer: shadcn/ui for Roblox juice.** Not a package you depend on. The agent copies the component into your game and you own it.

```
You:   "add a coin pickup effect and sound"
Agent → registry: find "coin_pickup"
Agent: copies the effect file + sound into src/, you upload the sound, done
Code:  Juice.play("coin_pickup", part)
```

**Principles**

1. **Copy, don't install.** Files land in the user's project. They can read and edit everything.
2. **We host nothing.** The registry is this GitHub repo (`registry/index.json`). Sounds are uploaded to the *user's own* Roblox account, so no shared asset can be deleted and break everyone's games.
3. **Made by us, licensed clean.** We don't repackage Creator Store or community assets (unclear redistribution rights, can vanish, inconsistent style). Everything is original or CC0, and its source is listed in the index.
4. **One consistent style.** A small set that looks and sounds like it belongs together beats a huge mixed bag.
5. **Agent-native.** One JSON file describes every item: what it is, which files to copy where, what to do after. An agent reads it once and installs anything.
6. **Small and good first.** Start with ~6 effects and ~9 sounds, done well. Grow on request, with a quality bar on contributions.

**Shape**

| Piece | What it is |
|---|---|
| `registry/index.json` | Every item: name, kind, tags, files, install steps, license |
| `registry/juice/` | The tiny runtime: `Juice.play`, `Juice.vfx`, `Juice.sfx`, `Juice.music` |
| `registry/vfx/` | One Luau file per effect: plain ParticleEmitter settings, tuned |
| `registry/sfx/` | Original sounds (`.ogg`), generated by `registry/tools/gen_sfx.py` |
| `registry/music/` | Planned: lobby loop, gameplay loops, victory and fail stings |

**Milestones**

- [x] v0: runtime, 6 effects, 9 UI and gameplay sounds, index format, install guide
- [ ] Previews on the website (GIF per effect, playable clip per sound)
- [ ] Music pack: 5–10 tracks (commission, or CC0 / CC-BY with credit)
- [ ] Own particle textures (replace the built-in ones), uploaded like sounds
- [ ] Packs per game type (`obby-pack`, `tycoon-pack`, `simulator-pack`), wired into the specs so every game ships with sound and effects by default
- [ ] MCP server tools: `search`, `get`, `add`
- [ ] CLI fallback: `npx baseplate add coin_pickup`

## 2. Store assets: icons and thumbnails

No user posting needed. The agent already knows the game (type, name, theme), so it can:

- **Generate** a Roblox-style icon and thumbnails from that context, or
- **Capture** real screenshots with a Studio plugin that moves the camera through the map, then add a title and polish.

Both need a check before upload, since Roblox moderates every image. Captured screenshots are closer to the real game and less likely to look misleading.

## 3. Fastlane for Roblox

`baseplate ship`: build, upload, configure and go live, callable by an agent. Built on official Open Cloud APIs with an API key, never the user's login cookie (fragile, against the ToS, puts accounts at risk).

| Step | Automatable? |
|---|---|
| Build `.rbxl` with Rojo | Yes, locally |
| Publish a place version | Yes, Open Cloud |
| Upload images, audio, models | Yes, Open Cloud Assets API (this also installs sounds from section 1) |
| Game passes, dev products | Largely, via newer Open Cloud endpoints |
| Name, description, settings | Partly |
| Icon and thumbnails | Patchy |
| First-time creation, maturity questionnaire, going public, API Services toggle | Mostly manual |

Steps without an API become a **guided checklist**: the CLI opens the exact Creator Hub page, says what to click, then confirms the result through the API before moving on. Re-check the Open Cloud docs before building; coverage changes often.

## Order

1. **Component library** (VFX + sounds). Smallest, ships value today.
2. **Fastlane core**: asset upload + place publish. Turns "upload the sound yourself" into one command.
3. **Store assets**, reusing the fastlane's image upload.
